# 任務：精簡 Markdown 表格內容

## 角色

你是一位專業的內容精煉專家，專精於識別並移除表格中的冗餘資訊，讓表格只呈現對主題最核心的內容。

## 目標

遍歷 `site/content/docs/` 下所有的 `_index.md` 檔案，分析每個表格的上下文與主題，移除不必要的補充說明、無關資訊和過度解釋，使表格精簡且聚焦。

## 執行步驟

1. **掃描檔案**
   - 找出 `site/content/docs/` 下所有的 `_index.md` 檔案
   - 列出包含表格的檔案清單

2. **分析表格**
   - 讀取每個 `_index.md` 的內容
   - 識別所有 Markdown 表格
   - 根據表格的上下文（標題、前後段落）判斷表格的主題

3. **執行精簡**
   - 依照下方判斷標準移除冗餘內容
   - 保留原有的 frontmatter（`---` 區塊）
   - 確保精簡後的表格仍然完整可用

4. **完成報告**
   - 列出已處理的檔案
   - 標註精簡的表格數量和移除的內容類型

## 判斷標準：什麼內容應該移除

### ✅ 應該移除的內容

1. **重複性補充說明** - 與主欄位語義重複的解釋
   ```markdown
   # 精簡前
   | 方法 | 說明 |
   |------|------|
   | `GET` | 獲取資源的方法。這個方法用於從伺服器請求數據，不會修改任何資料。 |

   # 精簡後
   | 方法 | 說明 |
   |------|------|
   | `GET` | 獲取資源，不修改資料 |
   ```

2. **顯而易見的資訊** - 從欄位名稱就能推斷的內容
   ```markdown
   # 精簡前
   | 顏色 | 色碼 | 說明 |
   |------|------|------|
   | 紅色 | #FF0000 | 這是紅色的十六進位色碼 |
   | 藍色 | #0000FF | 這是藍色的十六進位色碼 |

   # 精簡後（移除說明欄）
   | 顏色 | 色碼 |
   |------|------|
   | 紅色 | #FF0000 |
   | 藍色 | #0000FF |
   ```

3. **與主題無關的額外屬性** - 偏離表格核心目的的欄位
   ```markdown
   # 精簡前（主題：比較框架學習難度）
   | 框架 | 學習曲線 | 開發者 | 首次發布 | 授權 | GitHub Stars |
   |------|----------|--------|----------|------|--------------|
   | React | 中等 | Meta | 2013 | MIT | 200k+ |
   | Vue | 平緩 | 尤雨溪 | 2014 | MIT | 200k+ |

   # 精簡後（保留與主題相關的欄位）
   | 框架 | 學習曲線 |
   |------|----------|
   | React | 中等 |
   | Vue | 平緩 |
   ```

4. **過度修飾的形容詞** - 不影響理解的誇大用詞
   ```markdown
   # 精簡前
   | 特性 | 優點 |
   |------|------|
   | 快取 | 大幅提升效能，顯著減少伺服器負擔，帶來絕佳的使用者體驗 |

   # 精簡後
   | 特性 | 優點 |
   |------|------|
   | 快取 | 提升效能，減少伺服器負擔 |
   ```

5. **通用性建議** - 不針對特定項目的泛泛之談
   ```markdown
   # 精簡前
   | 工具 | 用途 | 建議 |
   |------|------|------|
   | Git | 版本控制 | 建議學習，這是每個開發者必備的技能 |
   | Docker | 容器化 | 建議學習，可以提升開發效率 |

   # 精簡後（移除通用建議欄）
   | 工具 | 用途 |
   |------|------|
   | Git | 版本控制 |
   | Docker | 容器化 |
   ```

6. **重複的範例或說明** - 每列都有類似的補充
   ```markdown
   # 精簡前
   | 參數 | 類型 | 範例 |
   |------|------|------|
   | name | string | 例如："John" |
   | age | number | 例如：25 |
   | active | boolean | 例如：true |

   # 精簡後
   | 參數 | 類型 |
   |------|------|
   | name | string |
   | age | number |
   | active | boolean |
   ```

### ❌ 不應該移除的內容

1. **區分性資訊** - 幫助區分不同項目的關鍵差異
2. **專業術語解釋** - 對理解主題必要的定義
3. **關鍵數值** - 具有參考價值的具體數據
4. **必要的上下文** - 沒有它表格會失去意義的資訊
5. **使用條件或限制** - 影響決策的重要約束

## 精簡原則

### 1. 主題聚焦原則
- 閱讀表格上方的標題和段落，確定表格的核心目的
- 只保留直接服務於該目的的資訊

### 2. 最小必要原則
- 問自己：「移除這個資訊後，讀者還能達成閱讀目的嗎？」
- 如果可以，就移除

### 3. 讀者導向原則
- 考慮目標讀者已有的背景知識
- 對專業讀者，可以省略基礎說明
- 對入門讀者，保留必要的解釋

### 4. 欄位整合原則
- 若多個欄位可以合併表達，考慮整合
- 若某欄位所有列的值都相同或近似，考慮移除並在表格說明中提及

## 精簡範例

### 範例一：API 端點說明

```markdown
# 精簡前
| 端點 | 方法 | 說明 | 回傳格式 | 認證需求 | 頻率限制 | 備註 |
|------|------|------|----------|----------|----------|------|
| /users | GET | 獲取使用者列表。此端點會返回系統中所有使用者的資料。 | JSON | 需要 | 100/分鐘 | 分頁支援 |
| /users/:id | GET | 獲取單一使用者。透過 ID 查詢特定使用者的詳細資料。 | JSON | 需要 | 100/分鐘 | - |
| /users | POST | 建立新使用者。提供必要資料以在系統中建立新使用者。 | JSON | 需要 | 50/分鐘 | 需驗證欄位 |

# 精簡後
| 端點 | 方法 | 說明 | 備註 |
|------|------|------|------|
| /users | GET | 獲取使用者列表 | 支援分頁 |
| /users/:id | GET | 獲取單一使用者 | - |
| /users | POST | 建立新使用者 | 需驗證欄位 |

> [!NOTE]
> 所有端點皆需認證、回傳 JSON 格式，頻率限制為 50-100 次/分鐘。
```

### 範例二：設計模式比較

```markdown
# 精簡前
| 模式 | 類型 | 目的 | 適用場景 | 優點 | 缺點 | 相關模式 | 實作難度 |
|------|------|------|----------|------|------|----------|----------|
| 單例模式 | 創建型 | 確保類別只有一個實例 | 當你需要確保全域只有一個實例時使用，例如設定管理、日誌記錄等場景 | 節省資源、全域存取點 | 難以測試、隱藏依賴 | 工廠模式 | 簡單 |
| 觀察者模式 | 行為型 | 定義物件間的一對多依賴 | 當一個物件狀態改變需要通知其他物件時使用，例如事件系統、訂閱機制 | 鬆耦合、支援廣播 | 可能造成記憶體洩漏 | 發布訂閱 | 中等 |

# 精簡後
| 模式 | 類型 | 目的 | 適用場景 |
|------|------|------|----------|
| 單例模式 | 創建型 | 確保類別只有一個實例 | 設定管理、日誌記錄 |
| 觀察者模式 | 行為型 | 定義物件間的一對多依賴 | 事件系統、訂閱機制 |
```

```markdown
# 精簡前
| 參數 | 簡寫 | 類型 | 必填 | 預設值 | 說明 |
|------|------|------|------|--------|------|
| --output | -o | string | 否 | ./dist | 指定輸出目錄。這個參數讓你可以自訂編譯結果的輸出位置。 |

| 參數 | 簡寫 | 預設值 | 說明 |

```

## 注意事項

1. **保守刪除** - 如不確定是否應移除，傾向保留
2. **保持完整性** - 精簡後的表格必須仍然有意義且可用
3. **補充說明** - 若移除大量共通資訊，可在表格下方用一句話補充
4. **格式一致** - 精簡後確保表格對齊正確

## 開始執行

請掃描 `site/content/docs/` 資料夾，找出所有包含表格的 `_index.md` 檔案，分析每個表格的主題與上下文，判斷哪些內容可以精簡，列出建議後執行修改。
