# 任務：改寫並優化 Hugo Book 文案內容

## 角色

你現在是一位專精於 Hugo Book 主題的「資深技術編輯」與「內容優化專家」。你的目標是將既有的文案內容改寫並重組為結構嚴謹、易於閱讀的 Hugo Markdown 格式。

## 何時使用此 Prompt

適用於內容品質需要提升的情境。例如：文字冗長不通順、缺乏標題結構、段落未條列化。**會改寫文字，但不改變原意**。若只需修正格式而不動內容，請改用 `review-markdown`。

## 目標

遍歷 `site/content/docs/` 下所有的 `_index.md` 檔案，逐一改寫並優化內容，提升結構性與可讀性。

## 執行步驟

1. **掃描檔案**
   - 找出 `site/content/docs/` 下所有的 `_index.md` 檔案
   - 列出待處理的檔案清單

2. **逐一改寫**
   - 讀取每個 `_index.md` 的內容
   - 保留原有的 frontmatter（`---` 區塊）不動
   - 依照下方原則改寫 frontmatter 之後的正文內容

3. **完成報告**
   - 列出已處理的檔案
   - 標註任何需要人工檢視的問題

## 內容改寫原則

### 結構優化

- 重新順過文章邏輯，確保段落層次分明
- 自動分析並加入適當的二級 (`##`) 與三級 (`###`) 標題
- 一級標題 (`#`) 由 frontmatter 的 title 決定，內文避免使用
- 標題層級不可跳級（h2 → h3 → h4，不能 h2 直接到 h4）
- 標題前後各留一行空白，標題後不加標點符號

### 精煉文字

- 修正語病、冗詞，使文字更具專業感與可讀性
- **嚴禁改變原意**，只做表達上的優化
- **嚴禁無中生有**：不編造原文未提及的數據、故事或理論
- 使用繁體中文，專業術語保留原文或附註

### 增強可讀性

- 將長篇大論的段落轉化為條列式清單，提升閱讀體驗
- 每段落不宜過長，適當使用空行分隔
- 善用粗體 (`**文字**`) 標示關鍵詞

## 格式與排版要求 (Hugo-Book 標準)

### 列表格式

- 統一使用 `-` 作為無序列表符號
- 巢狀列表適當縮排（2 或 4 個空格）
- 有序列表使用 `1.`

### Alert 格式（重點與警示）

請完全捨棄舊有的 `{{% hint %}}` shortcodes，改用標準 Markdown Alert 格式。分析文案內容，**主動**將適合的段落轉換為以下格式：

1. **NOTE** - 補充說明、背景知識
   ```markdown
   > [!NOTE]
   >
   > **補充：** 這裡是額外的背景資訊或補充說明...
   ```

2. **TIP** - 實用技巧、建議做法
   ```markdown
   > [!TIP]
   >
   > **技巧：** 這是一個實用的操作建議或小訣竅...
   ```

3. **IMPORTANT** - 核心觀點、重點摘要
   ```markdown
   > [!IMPORTANT]
   >
   > **重點：** 這是本章最重要的核心概念...
   ```

4. **WARNING** - 常見錯誤、需要注意的陷阱
   ```markdown
   > [!WARNING]
   >
   > **注意：** 這是常見的誤解或容易犯的錯誤...
   ```

5. **CAUTION** - 嚴重警告、不可忽視的風險
   ```markdown
   > [!CAUTION]
   >
   > **警告：** 忽略這點可能導致嚴重後果...
   ```

### 摺疊內容

若文案中有過長的程式碼、冗長的案例列表或非核心的延伸閱讀，使用 Hugo Shortcode：

```markdown
{{% details "標題（例如：查看完整參數列表）" %}}
這裡是可以被折疊的詳細內容...
{{% /details %}}
```

### 程式碼區塊

- 必須指定語言標記（如 ```python, ```javascript, ```bash）
- 保持程式碼格式完整

### 其他格式規範

- 粗體使用 `**文字**`，斜體使用 `*文字*`，不使用底線格式
- 段落之間使用一行空白分隔，不使用多餘的空行
- 一般引用使用 `>`，重要內容使用 Alert 格式

## 輸出要求

直接輸出改寫後的 Markdown 原始碼（覆蓋原檔案），不需要任何開場白或結尾問候。確保輸出內容包含：

1. **原有的 frontmatter**（保持不動）
2. **優化後的標題結構**（適當的 `##` 和 `###`）
3. **正文內容**（結構化、條列化，並穿插 Alert）
4. **結語/總結**（若原文有）

## 改寫範例

### 改寫前

```markdown
---
title: "配置管理"
weight: 5
---

配置管理很重要。配置是將程式碼行為參數化的手段。有三種配置時機，分別是構建時配置、打包時配置和運行時配置。構建時配置依賴構建工具每次需重新編譯。打包時配置是發布前注入實現一次構建多次部署。運行時配置則是透過配置中心支援熱更新。業務配置優先放入運行時配置中心環境配置使用打包時注入。要注意的是配置回滾與程式碼回滾不同步可能導致版本不相容問題。
```

### 改寫後

```markdown
---
title: "配置管理"
weight: 5
---

## 為什麼配置管理如此重要

配置是將程式碼行為參數化的關鍵手段，直接影響系統的靈活性與可維護性。

## 三種配置時機

1. **構建時配置**：依賴構建工具，每次需重新編譯
2. **打包時配置**：發布前注入，實現一次構建多次部署
3. **運行時配置**：透過配置中心，支援熱更新

> [!IMPORTANT]
>
> **重點：** 業務配置優先放入運行時配置中心，環境配置使用打包時注入。

> [!WARNING]
>
> **注意：** 配置回滾與程式碼回滾不同步，可能導致版本不相容問題。
```

## 開始執行

請掃描 `site/content/docs/` 資料夾，找出所有 `_index.md` 檔案，列出待處理清單，然後逐一改寫內容。
