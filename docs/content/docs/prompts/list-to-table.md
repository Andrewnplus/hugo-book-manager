# list-to-table

分析條列式內容，將適合的條列式轉換為 Markdown 表格。

## 用途

- 將鍵值對列表轉為表格
- 將比較列表轉為表格
- 提升資訊的組織性和可讀性

## 使用方式

```bash
# 產生 prompt
./gradlew generatePrompt -Ptype=list-to-table

# 儲存到檔案
./gradlew generatePrompt -Ptype=list-to-table -Poutput=PROMPT.md
```

## 完整 Prompt

以下是完整的 Prompt 內容，可直接複製使用：

---

````markdown
# 任務：將條列式轉換為 Markdown 表格

## 角色

你是一位專業的內容結構優化專家，專精於將散亂的條列式資訊整理成結構化的表格，讓內容更易於閱讀和比較。

## 目標

遍歷 `site/content/docs/` 下所有的 `_index.md` 檔案，分析條列式內容，將適合的條列式轉換為 Markdown 表格，提升資訊的組織性和可讀性。

## 執行步驟

1. **掃描檔案**
   - 找出 `site/content/docs/` 下所有的 `_index.md` 檔案
   - 列出待分析的檔案清單

2. **分析條列式**
   - 讀取每個 `_index.md` 的內容
   - 識別所有條列式（無序列表和有序列表）
   - 評估每個條列式是否適合轉換為表格

3. **執行轉換**
   - 將適合的條列式轉換為表格
   - 保留原有的 frontmatter（`---` 區塊）
   - 確保表格格式正確

4. **完成報告**
   - 列出已處理的檔案
   - 標註轉換的條列式數量

## 判斷標準：何時應該轉換為表格

### ✅ 適合轉換的情況

1. **鍵值對列表** - 每個項目都是「名稱：說明」的格式
2. **比較列表** - 列出多個項目的相同屬性
3. **多屬性列表** - 每個項目包含多個結構化屬性
4. **步驟與說明** - 步驟序號對應說明
5. **優缺點對照** - 優點和缺點的對比

### ❌ 不適合轉換的情況

1. **敘述性列表** - 每個項目是獨立的段落或完整句子
2. **巢狀列表** - 包含多層子項目的列表
3. **不規則列表** - 項目之間沒有統一的結構
4. **簡短清單** - 只有 2-3 個簡單項目
5. **程式碼或指令列表** - 包含程式碼片段的列表

## 轉換範例

### 範例一：鍵值對列表
```markdown
# 轉換前
- 變數名稱：儲存資料的容器
- 函數：可重複使用的程式碼區塊
- 類別：物件的藍圖

# 轉換後
| 術語 | 說明 |
|------|------|
| 變數名稱 | 儲存資料的容器 |
| 函數 | 可重複使用的程式碼區塊 |
| 類別 | 物件的藍圖 |
```

### 範例二：比較列表
```markdown
# 轉換前
- Python：易學、動態類型、廣泛應用
- Java：企業級、靜態類型、跨平台
- JavaScript：瀏覽器原生、事件驅動、全端開發

# 轉換後
| 語言 | 特性 | 類型系統 | 應用場景 |
|------|------|----------|----------|
| Python | 易學 | 動態類型 | 廣泛應用 |
| Java | 企業級 | 靜態類型 | 跨平台 |
| JavaScript | 瀏覽器原生 | 事件驅動 | 全端開發 |
```

## 注意事項

1. **保守原則** - 如果不確定是否應該轉換，保持原狀
2. **保留上下文** - 表格前後的說明文字要保留
3. **檢查連貫性** - 確保轉換後的內容與前後文連貫
4. **保持一致性** - 同一份文件中相似的條列式應採用相同處理方式

## 開始執行

請掃描 `site/content/docs/` 資料夾，找出所有 `_index.md` 檔案，分析其中的條列式，判斷哪些適合轉換為表格，列出建議後執行轉換。
````

| 原始格式 | 建議格式 |
|----------|----------|
